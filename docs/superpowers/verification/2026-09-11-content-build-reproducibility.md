# Content build reproducibility check

The full `content-build-reproducibility` suite was rerun on the foundations branch. Two successive `npm run content:build` executions produce byte-identical output (including `public/study.js`), so the build itself is deterministic.

The remaining failure is the final clean-tree assertion: the checked-in `public/study.js` was generated by a different dependency/toolchain snapshot and differs from the deterministic output produced by the current lockfile installation. The diff is inside the bundled Zod runtime (minified helper variable names and formatting), not in the foundation preferences code or authored content. Tests and browser runs regenerate this file as a side effect, so it is reverted and remains out of feature commits per the generated-artifact policy.
