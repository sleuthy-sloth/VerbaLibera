# VerbaLibera B2–C2 Roadmap Plan

> **For Hermes:** implement phase-by-phase with TDD per task (write failing test → minimal impl → lint/typecheck/build → commit). Each phase is independently shippable.

**Goal:** Grow VerbaLibera from A1 travel drills into an app that can carry a learner to B2 (and lay honest track toward C1/C2) through new learning modes — without breaking the local-first, no-LLM-judge architecture.

**Architecture:** New drill kinds ride the existing pipeline (Prisma `DrillKind` enum + migration → fixture seeds → `resolveSessionContent` → step UI → composer order). Curriculum stays data-driven (`fixture.ts` + `docs/content-authoring.md` + provenance scripts). Open production is assessed by constraint, not by AI judge, until/unless an optional judge is explicitly chosen.

**Tech Stack:** Next.js 16 / React 19 / TS / Prisma+Postgres / Kokoro TTS + faster-whisper STT sidecar (unchanged).

---

## Honest constraints (read first)

1. **No LLM judge in the stack.** B2+ free writing/speaking cannot be graded locally. All open-production modes below are designed checkable-by-constraint (exact variants, slot validation, error-spotting keys, self-assessment rubrics) or human-in-the-loop (record-and-compare, export to tutor/Anki).
2. **Content is the bottleneck, not code.** 32 A1 patterns → B2 needs ~150–250 patterns + ~2,000–4,000 vocab items across 4 languages. Authoring throughput (fixture + WAVs + provenance + STT screen + listen) is the schedule driver. The plan front-loads authoring tooling.
3. **CEFR claims must be mapped, not marketed.** Never label content B1/B2 until a `cefr` field + coverage checklist exists (Phase 1). The app earns each level publicly.

## Phase 0 — CEFR spine (1 session)

**Objective:** Every concept carries a level; coverage is measurable.

- Create: `docs/cefr-coverage.md` (level definitions used, per-language checklists)
- Modify: `prisma/schema.prisma` (add `cefr String @default("A1")` to `ConceptBlock` + migration), `src/features/curriculum/types.ts` + `fixture.ts` (`makeConcept` stamps `cefr: 'A1'` on all 32 existing patterns)
- Test: `tests/cefr-spine.test.ts` — all concepts have valid CEFR tag; coverage counter reports 32×A1 / 0×others
- Verify: `npm run prisma:validate && npm run test -- tests/cefr-spine.test.ts`

## Phase 1 — B1 bridge: six checkable drill kinds (2–3 sessions)

**Objective:** Six new drill kinds that run on the current judge (exact-match + slot validation), each with UI + composer support.

| # | Kind | What it teaches | Check mechanism |
|---|------|-----------------|-----------------|
| 1 | `CLOZE` | Grammar in context (articles, prepositions, endings) | Exact blank fill vs accepted variants |
| 2 | `CONJUGATION` | Verb tables (passé composé, futuro, pretérito…) | Exact form vs variants; tense/person prompt |
| 3 | `ERROR_SPOT` | Proofreading (agreement, word order, false friends) | Tap-the-error choice vs key |
| 4 | `DIALOGUE_REPAIR` | Discourse: pick the fitting reply in a 3-turn exchange | Choice vs key + why-note |
| 5 | `DICTATION` | Listening: type what you hear (STT-adjacent, uses TTS audio) | Exact/normalized match vs transcript |
| 6 | `READING_COMP` | Short passage (80–150 words) + 2–3 questions | Choice vs key |

- Files per kind: `DrillKind` enum + migration (one migration for all six) → `fixture.ts` seed shape → `resolve-session-content.ts` → step component (e.g. `ClozeBuilder.tsx`, following `WordBuilder.tsx`/`PictureChoice.tsx` patterns) → composer unchanged (all are `DRILL`)
- Seed content: 2 patterns × 6 kinds × French first (12 seeds + 24 WAVs), proving the authoring loop before scaling
- Tests per kind: resolver test + component test (radiogroup/keyboard/a11y like `PictureChoice`) + e2e walk extension
- Verify per kind: `npm run test`, `npx eslint <files>`, `npm run build`

## Phase 2 — Authoring throughput (1–2 sessions)

**Objective:** 10× content velocity without quality loss.

- `scripts/new-pattern.mjs`: scaffolds fixture seed + audio manifest entries + provenance stubs from one prompt (`--lang fr --pattern <id> --cefr B1`)
- `services/voice/scripts/stt_check.py`: extend to new kinds (dictation transcripts, conjugation forms)
- `docs/content-authoring.md`: B1+ authoring rules (distractor quality for choices, acceptable-variant policy, CEFR tagging guide)
- `tests/content-validation`: fixture lint (unique ids, every drill has key/variants, every audio id has WAV + provenance) — runs in CI
- Verify: scaffold one real B1 pattern end-to-end through the script

## Phase 3 — B1 curriculum expansion (ongoing, per language)

**Objective:** Fill the B1 checklist: past tenses, future, conditional essentials, pronouns (y/en, ci/ne, se), comparatives, connected discourse (linkers), everyday domains (work, health, housing, bureaucracy).

- ~40 B1 patterns/language × 4 languages, authored via Phase 2 tooling, each with drills + audio + provenance
- `docs/cefr-coverage.md` updated per landing; dashboard shows per-level progress honestly (counts only, no inflated claims)
- Verify: content-validation green + STT screen + human listen per batch (checklists exist per language)

## Phase 4 — Productive skills without a judge (2 sessions)

**Objective:** Speaking/writing practice that stays honest with local-only checking.

- `SHADOWING`: listen → record → waveform-compare vs model (extends existing `VoiceRecorder`; score = duration/energy similarity, labeled "pronunciation rhythm, not grading")
- `GUIDED_WRITING`: constrained prompts (e.g. "describe your morning in 5 sentences using passé composé") with self-assessment rubric checklist (not auto-graded — stored for review, exportable to Anki)
- `CONVERSATION_SIM`: branching scripted dialogues (3–5 turns, learner picks/adapts replies; branches authored, fully checkable)
- All three labeled in UI as practice, never as assessment — mastery still gates on checkable drills
- Tests: component + e2e; privacy: recordings stay in-memory/local like current `VoiceRecorder`

## Phase 5 — B2 core (multi-session, content-led)

**Objective:** Subjunctive essentials, conditionals, passive, reported speech, relative clauses, register (tu/vous, formal email), argumentation (opinion + connectors), domain depth (news, work meetings, culture).

- Same machinery as Phase 3 (~60 B2 patterns/language); adds `READING_COMP` long-form (250–400 words) and `DIALOGUE_REPAIR` multi-turn
- Optional: `LLM_JUDGE` behind explicit opt-in + BYO key for free-writing feedback (spec'd but NOT built until chosen — this is the one architectural fork; default stays local)

## Phase 6 — C1/C2 track (fog — specify after B2 lands)

Candidates, not commitments: idiom/collocation banks, nuance discrimination (near-synonym choice), long-form listening (podcast-style generated audio + comp), stylistic rewriting (formal↔informal with authored keys), debate prep (structured argument + connector drills), extensive reading library with comp layers. C2 production grading without a human remains out of scope for auto-assessment by design.

## Risks & open questions

1. **Authoring bandwidth** is the critical path — 4 languages × 100+ patterns is hundreds of WAVs + listen reviews. Mitigation: Phase 2 tooling first; consider shipping French-complete B1/B2 before cloning to other languages.
2. **Kokoro prosody at B2 complexity** — long/conditional sentences may TTS poorly; STT screen catches worst cases, listen checklist catches the rest. May need per-clip regeneration policy.
3. **The judge fork (Phase 5)** — BYO-key LLM grading vs staying fully local is a product identity decision. Recommend deferring until B1 ships and real learners weigh in.
4. **Scope discipline** — C1/C2 stay fog until B2 is real. No code for Phase 6 in this plan.
